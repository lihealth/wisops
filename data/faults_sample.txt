# 格式: fault_name|solution_name|solution_description
# 说明: 以 # 开头的行会被忽略

CPU告警|检查高负载进程并限流|使用 top/htop 定位高占用进程，先限流再排查是否有异常任务或死循环。
MySQL连接数过高|排查慢查询并优化连接池|检查慢查询日志，优化索引与 SQL，并调整应用连接池上限与超时配置。
磁盘空间不足|清理日志并扩容磁盘|先清理历史日志和临时文件，评估增长趋势后进行磁盘扩容。
服务频繁重启|检查崩溃日志与健康检查配置|查看应用日志和系统日志，确认 OOM、探针配置或启动参数是否异常。
接口响应慢|定位热点接口并加缓存|用 APM 定位慢接口，优化数据库访问并增加热点数据缓存。
Redis内存告警|排查大 Key 与过期策略|使用 memory 分析命令定位大 Key，设置合理 TTL 并优化淘汰策略。
网络连接超时|检查链路与防火墙策略|逐跳检查网络连通性，确认安全组/防火墙策略和 DNS 配置是否正确。
Nginx 502错误|确认上游服务可用性|检查 upstream 服务进程和端口状态，必要时提升超时配置并重启服务。
Kafka消息积压|增加消费并行度并排查慢消费者|查看 consumer lag，提升消费者并发，定位消费逻辑瓶颈。
容器 OOMKilled|限制内存并优化应用占用|设置 requests/limits，排查内存泄漏并优化对象生命周期。
