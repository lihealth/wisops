# WisOps V1.8 与 V2.0 功能差距清单

> 评估基线：`PRD_V2.md`（V2.0 目标态）  
> 当前基线：`CHANGELOG.md` v1.8.0 + 现有代码实现

## 一、结论（先看这个）

- **V2.0 P0 主链路已基本打通**：Schema 2.0、抽取审核闭环、推荐、TRIGGERS、看板基础指标均已可用。
- **距离 V2.0 完整版仍有缺口**，集中在三类：
  - Graph-RAG 在 Dify 工作流中的正式编排与前端展示
  - 权限与审计（SEC）
  - 交付物与外部系统深度集成（完整测试报告、CMDB/工单自动化等）

## 二、按模块对比（V1.8 现状）

### SCH（图谱本体 2.0）

- **已完成**
  - 多实体与多关系 Schema（含 `TRIGGERS`、`DOCUMENTED_IN` 等）
  - `TRIGGERS` 审计字段：`confidence/method/rule_name`
  - 文档追溯链路：`document_id -> DOCUMENTED_IN(chunk_ref) -> Solution/Fault`
- **差距**
  - `Person` 相关能力未形成可用业务流（仅 schema 侧准备）

### DATA（公开数据与混合知识库）

- **已完成**
  - GAIA 导入
  - LogHub 可追溯导入（含 `source_file/source_line/matched_pattern`）
  - 导入验收脚本与流程
  - Stack Exchange **`Posts.xml`** 清洗与批量写入图谱（`scripts/import_stackoverflow.py`，`data_source=stackoverflow`，见 `data/stackoverflow/README.md`；全量 dump 需自行从 archive 下载）
- **已完成（补充）**
  - **`DATA_IMPORT_REPORT_V2.md`** 已完成（含数据量快照、4 类来源说明、全量恢复命令）

### EXT（动态构建与知识沉淀）

- **已完成**
  - `submit -> jobs -> queue -> approve/reject` 全链路
  - 审核队列 **批量** 通过/拒绝（`batch-approve` / `batch-reject` + portal 多选）
  - LLM 抽取（含 fallback）
  - approve 双写图谱 + Dify
  - `document_id` 追溯索引与反查 API
- **差距**
  - 工单自动触发抽取（Webhook/定时集成）未完成

### RETR（图谱增强检索与推荐）

- **已完成**
  - `/graph/context`
  - `/graph/recommend`（向量优先 + fallback）
  - Qdrant `fault_vectors` 同步
  - 门户问答页：模式切换（纯 RAG / 图谱融合 / 自动）及图谱摘要卡、相似故障推荐卡
- **差距**
  - Dify 工作流内“正式 Graph-RAG 编排”未固化（你之前明确暂缓）

### PORTAL（统一门户）

- **已完成**
  - `/extract`、`/sop`、`/dashboard`、`/graph` 多标签增强
  - TRIGGERS 审计页
  - 文档追溯页（抽取页 + 图谱页）
  - `/assets` 资产管理页
  - `/chat` 图谱融合展示与模式切换
  - `/incidents` **工单沉淀页**（列表 + 详情 + 录入表单，含 Fault/Solution/Asset 关联）

### INT（外部系统集成）

- **已完成**
  - `/assets/sync`、`/assets`
  - `/alerts/ingest`、`/alerts`
  - `/incidents`、`/incidents`
- **差距**
  - 外部 CMDB/监控/工单系统的真实对接编排仍以手工或本地调用为主

### OPS（知识运营与看板）

- **已完成**
  - `/ops/stats`、`/ops/stats/growth`
  - `source_distribution` 统计修复
- **差距**
  - 完整运营报表导出流程未固化（可视化与导出维度仍可增强）

### SEC（权限、审计与安全）

- **已完成**
  - `.env` 化与 `.env.example` 完整示例（含 `GRAPH_API_KEY`、`AUDIT_MAX_ENTRIES`）
  - **`X-API-Key` 中间件**：`GRAPH_API_KEY` 设置后写操作强制校验；未设置跳过（开发模式）
  - **审计日志**：`audit_middleware` 自动记录全部写操作；`GET /admin/audit-log` 可查询
  - **角色系统**（portal）：`admin` / `engineer` / `readonly` 三档；导航/路由/按钮按 `can()` 条件渲染；左下角角色切换器
- **剩余差距**
  - 角色分配仍为前端 localStorage（无服务端认证），生产需对接认证系统
  - 审计日志内存态（重启丢失），生产应落库
